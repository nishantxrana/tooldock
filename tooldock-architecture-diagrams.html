ToolDock Architecture, Flows, and Deployment

These diagrams are derived from the current codebase in ui/ (React + Vite SPA, same-origin Azure DevOps proxies, session store + optional encrypted PAT vault). No backend service or database exists in this repository.

System Context Frontend Component Architecture Read/Write Data Flow Connection + Security Flow Deployment and Runtime Infrastructure

1) High-Level System Context

Browser-only SPA calling Azure DevOps through same-origin proxy paths /ado and /vsrm.

2) Frontend Component and Dependency Architecture

Router and tools come from a registry; route guards enforce connection and project selection; hooks + API modules wrap Azure DevOps calls.

3) Request and Data Flow (Read + Write Paths)

All network calls use adoRequest; reads dominate. CSV Import is the only write flow and performs GET-authoritative then PUT-full-body update.

4) Connection, Session, and Security Flow

Route-level connection gate + project gate, with default memory-only token handling and opt-in encrypted persistence.

5) Deployment and Runtime Infrastructure

Single frontend artifact (dist/) with host-level rewrites; no server app in repo. Vercel adds edge middleware checks before proxy rewrites.

Repository facts reflected here: no backend service in repo, no database layer, and no GitHub Actions workflow files found under .github/workflows/. If those are added later, add CI/CD and backend runtime diagrams.
